Components

Every component the kit ships, rendered by the kit's own plugin with the starter course's data. What you see here is what a course's build produces.

Building blocks

Props and slots only; they never read the page's data. Use them anywhere.

  • arrow-link A link with a trailing arrow. The label is the slot; href and any other attribute pass through to the <a>.
  • assigned-list A labelled list of readings or deadlines. Renders nothing when empty.
  • callout A highlighted aside. The content is the slot.
  • card-list A list of cards, each linking to a page. A card shows the page's code, name and description unless the slot supplies its own content.
  • codepen-embed A live code sample: a header with actions, then the CodePen embed prefilled with the code.
  • download-button A download link with an icon. The label is the slot.
  • eyebrow A small line above a heading. The content is the slot.
  • link-list A list of links, each with a name and an optional description.
  • link-section A titled list of links. Renders nothing when there are no items and no empty text.
  • meeting-card One class meeting in a week's list: the date down the left, the slot beside it. Marks itself as the scope <today-marker> highlights.
  • meeting-decks A meeting's deck links, each on its own line: the slides, then any addendum. Renders nothing without either.
  • table-rubric A grading rubric as a table: criteria down, performance levels or a due date and points across.
  • today-link The page's Today shortcut: a button that jumps to the #today element <today-marker> picks. Hidden until there is one, and in print.
  • today-marker <today-marker> marks today's class meeting. A host renders it once, adds data-today-host="<name>" to its root, and puts data-date on what it lists; the page's <today-link> jumps to the result. A script flags every [data-date] element listing today's campus date (the site's institution.timezone): data-today, aria-current="date" and a visible "Today" flag (data-today-label overrides the text; a table row gets it in its first cell). One element gets id="today" for the link: today's, else the next meeting, else the first (before the term) or last (after it); never a no-class day. A host puts data-today-scope on the element that should carry the id and the highlight (the schedule's .meeting), otherwise the dated element itself does. An element that already has an id gets an empty <span id="today"> inside it instead, and an existing #today wins.
  • week-block One bordered block per week: a tinted header band, then the slot.

Site sections

Parts of a course site. Most read the course's data files, so they work with no props.

  • copyright The copyright line: the build year and the site's author. Reads site.
  • course-documents The "Additional resources" list: the entries of course.documents, each a link with an optional description. A PDF is listed only when the build produced PDFs. Renders nothing when there are none.
  • course-summary The course home page's body: the description, the instructor, the syllabus and the schedule. Reads the course, grading, schedule, instructor and term data; it takes no props.
  • demo-weeks The weeks that had a demo, one row per meeting: its demos, then its deck.
  • glossary-entry One glossary term as a <dt>/<dd> pair: the term, its definition, an optional signature, meta line and example, its tags, and where it was taught. Styled by <glossary-panel>, which holds the list.
  • glossary-panel The glossary's element: the plain list it wraps (the slot) stays when scripts do not run, and scripts/glossary.js replaces it with Review and Flashcards. One stylesheet covers both, since the script renders the same markup the server does.
  • glossary The course glossary page: every vocab and api slide as one tagged term, listed A to Z for readers without scripts and enhanced into Review and Flashcards by <glossary-panel>. Reads the glossary global.
  • grading The grade-weighting table and the grading scale. Reads the grading and scale data; it takes no props and renders nothing without grading.
  • instructor The instructor's details: photo, office, contact and hours. Reads instructor.
  • masthead The page header: institution, term, course title and the navigation. Reads site, term and course.
  • nav-links The site navigation as a list of links, marking the current page.
  • policies The policies section: one disclosure per entry in policies.json, open by default, each with an optional link to the full policy. Renders nothing without policies.
  • schedule-overview The schedule page's header: the meeting line, the key dates, and a row of jump links (Today, then one per month). Props are read in the template, since a setup script cannot see them.
  • schedule-weeks Every week of the term as a bordered block: its meetings (topics, readings, deadlines, deck and demos) beside the week's materials.
  • site-footer The page footer: course, institution, term, copyright and the links. Reads course, site and term.
  • slide-timetable Every slide deck as a timetable: one row per week, one column per meeting day.
  • syllabus The syllabus: outcomes, text, technology, coursework and grading. Reads the course, grading, scale, schedule and project data; it takes no props.

Practice worksheets

The widgets a practice worksheet is made of.

  • check-controls The Check and Reset buttons and the score line for one worksheet scope. practice.js shows them and fills the tally.
  • choice-list A radio group of lettered choices.
  • cite-panel A "?" disclosure listing the sources for a question.
  • practice-figure A question's inline SVG diagram, written out as authored. Its class vocabulary is styled by the worksheet stylesheet.
  • practice-fill A fill-in question: a word bank and a numbered list of blanks.
  • practice-grid A grid question: rows of choices across columns.
  • practice-judge A judge question: a verdict, then the one line of code that causes the problem.
  • practice-match A match question: a lettered bank and items that each take a letter.
  • practice-question One worksheet question: its prompt, sources, snippet and figure, then the control its kind needs.
  • practice-selfcheck A self-check question: reveal the answer, then tick what you got.
  • practice-terms A bank of terms, each opening its definition in a popover.
  • practice-tree A tree question: a snippet and its DOM tree with blanks to fill in.
  • practice-worksheet The practice worksheet page: heading, sections of questions, and the check controls. Reads the worksheet data a worksheet's .11tydata.js supplies.
