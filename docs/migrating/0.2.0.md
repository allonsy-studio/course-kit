# Migrating to 0.2.0

Notes for 0.2.0. The changelog entry links here. A course that builds on 0.1.x needs to do nothing to keep its site as it is; the sections below say what is new and what a course can now delete.

## Instructor icon links

`<instructor>` can show the email, the message link and the blog as icon links in the corner of its panel, instead of rows in the fact list. It is off by default: a site that changes nothing renders the markup it did in 0.1.x.

To take it, add one line to `_data/instructor.json`:

```json
"contactLinks": "icons"
```

A course that overrode `instructor.webc` only to get these icons (the CS230 course did, with its `instructorExtra.blogUrl` copy key) deletes that part of its override and its `instructorExtra` namespace: the kit's `instructor.blogUrl` replaces it. A course whose override also adds something else, such as a booking button, keeps the override until the kit has that too ([backlog](../backlog.md)).

## The syllabus contents list

`<syllabus>` now opens with a contents list: a row of links above the syllabus below 1100px and, from 1100px, a sticky column beside it that marks the part on screen (`aria-current="location"`). It is the list both course sites carried in their own `syllabus.webc`, and it is **on by default**, so a site on 0.1.x that upgrades gains it. The parts also gained ids (`outcomes`, `text`, `technology`; the others had them), which the list links to. Print and the syllabus PDF do not show it.

- A course that overrode `syllabus.webc` only to add the contents list deletes its override, and its `syllabusExtra` copy namespace (`contents`, `additionalOutcomes`): the kit reuses `document.contents` ("Contents") and has `syllabus.additionalOutcomes`. A course whose override changes other things keeps it and merges the kit's markup, or drops the parts it no longer needs.
- To leave the list out, set `"syllabusContents": false` in `course.json`, or write `<syllabus contents="false">`.
- If you styled `#syllabus` as a single column, check the page at 1100px and wider: with the list, the syllabus is two columns.

## The schedule page's row, and the chips' key

`<schedule-overview>` now ends its header with one sticky row: a link for each month, and the Hide past weeks toggle at its end.

- The Today link is gone from the row (`<today-link>` itself stays in the kit). Rows of today's class are still marked by `<today-marker>`.
- The month on screen is underlined and has `aria-current="location"`, set by a script in the component as the page scrolls. Each month link carries `data-first-week` and `data-last-week`, built from `scheduleMonths` (which now returns `last` as well as `week`).
- The Hide past weeks button, its status line and the `[data-schedule-tools]` wrapper moved from `<schedule-weeks>` into the row. `<schedule-weeks>` finds them in the page, so with no `<schedule-overview>` there is no toggle. The toolbar over the weeks is gone.
- The row is pinned from 640px wide, and the page's scroll padding follows its height so an anchor or a focused control is never under it. Below 640px it is a plain row.
- The key above the weeks shows the Test, Graded and Reading check chips alone; Practice keeps "not graded". `schedule.graded` is no longer a copy key.

A course that overrides `schedule-overview` or `schedule-weeks` takes these changes from the kit's copy: remove the Today link, move the toggle into the row, drop the toolbar, add the month mark. A course whose `strings.json` sets `schedule.graded` deletes it.

## The eyebrow above a page heading

The line of term and course code above the heading (`Fall 2026 · CS101`) repeated the masthead, so it is gone from the glossary, the schedule, the practice worksheet and the lesson plans index. A worksheet that sets `eyebrow` in its front matter still shows that label alone. `glossary.glossary` is no longer a copy key. The masthead does not print, but the footer does, with the course and the term; the syllabus's print-only term and title line stays, because the syllabus stylesheet hides the footer.

A course that overrides the glossary, `schedule-overview`, `practice-worksheet` or `layouts/lesson.webc` removes its own eyebrow the same way.
