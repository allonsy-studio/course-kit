# Migrating to 0.4.0

Notes for 0.4.0. The changelog entry links here. A course that builds on 0.3.x keeps building. In `0.x` a minor release can change what a page looks like or break an override, so the sections below say what changed and what a course that overrides a kit file has to do. The release is a minor, not a patch, because the rubric's Due column and the phone layout of a document change for every course that uses them.

## The rubric's Due column is the short form

`<table-rubric>` writes a milestone's due date as "Fri, Oct 23, 12:00PM", where it wrote "Friday, October 23, 2026, 12:00PM". The long form wrapped to four lines in a narrow column. The time is also normalized now ("12:00 pm" reads "12:00PM"), as it is on the schedule.

- To keep the long form in one table, write `<table-rubric date-style="full">`.
- A course that overrides `table-rubric.webc` takes the kit's copy, or changes its own Due cell to `dateIn(criterion.due, "short")`.
- Nothing else changes: the key dates on the schedule page, the syllabus and the lesson plans keep the long form, and due labels already used the short one.

## Date formats

The new `dateFormats` option sets the language and the two named forms of every date the kit writes; see [Date formats](../configuration.md#date-formats). It is optional, and the defaults are the English forms the kit used.

- `fullDate` and `compactDate` (the short form) read it, and so do the data files that import them. A course script that imports `fullDate` from `@allons-y/course-kit/filters` gets the course's format.
- `<schedule-overview date-style="short">` writes the project and exam key dates short, for a course whose key dates wrap.

## The booking button

Set `booking` in `instructor.json` and the kit renders the button; see [A booking button](../data-files.md#a-booking-button).

```json
{ "booking": { "url": "https://calendar.example.edu/appointments/sam", "label": "Book an appointment" } }
```

- A course that overrides `instructor.webc` only to add `<book-appointment>` after the note deletes the override, and its `.facts-column:has(> .links) > .book-appointment` rule with it. The kit's button sits where the override put it, on its own last line, in the default panel, the icon panel and the card.
- A course whose `_includes/book-appointment.webc` is its own keeps it: a file in `_includes` wins over the kit's by name, and the kit's `<instructor>` places the tag. A course that deletes that file takes the kit's button, which reads the same `instructor.booking` and falls back to the `instructor.bookAnAppointment` copy key. The course's own `bookAppointment` copy namespace can go.
- The kit's stylesheet now has `a.cta-button[href]`, the accent pill. A course that styled its own `.cta-button` in a scoped block gets the same pill from the base first; its own rules still apply on top.
- A course whose `instructor.json` already has a `booking` and no override gains the button on every page that has the instructor panel (the home page and the syllabus).

## The contents list on a phone

Below 900px the document layout puts its Contents list after the page, where it put it above. A page with a long list no longer buries its h1 under it. The source order is unchanged (page first), so a screen reader reads in the same order the screen shows. Above 900px the list is still the column beside the page. A course that overrides `layouts/document.webc` has no change to make; one with its own CSS for `.doc-layout[data-contents]` at that width checks that it does not put the list first.

## Two fixes to the base stylesheet

- A `.separators` row that is also `.print-only` is hidden on screen and a flex row in print, and one that is `.screen-only` is hidden in print. `.separators { display: flex }` outranked the two utilities before.
- Every link that is a direct child of a cell of a `.table-light` table is a 44px target (`:where(td, th) > a`), where only a link that was the whole cell was. A cell with two links now gives each its own 44px line.
