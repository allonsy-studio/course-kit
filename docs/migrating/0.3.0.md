# Migrating to 0.3.0

Notes for 0.3.0. The changelog entry links here. A course that builds on 0.2.x keeps working; the sections below say what changed and what a course that overrides a kit file, or sets a copy key, has to update. In `0.x` a minor release can break an override, so read this before taking it.

## The deck follows the system theme

The slide deck no longer has a light, dark and system button. Its `T` shortcut, the choice it saved in `localStorage` and the `theme-restore.js` script are gone, and the deck follows the system's light or dark setting like the rest of the site.

- A course that sets `deck.cycleColorTheme` in `strings.json` deletes that entry, or the build stops with "is not a copy key".
- A course that copied `layouts/deck.webc`, `assets/scripts/deck.js` or `theme-restore.js` to keep the button takes the kit's copies, or deletes its own.
- A browser keeps its old `theme` entry in `localStorage`; nothing reads it any more.

## The schedule page's row, and the chips' key

`<schedule-overview>` now ends its header with one sticky row: a link for each month, and the Hide past weeks toggle at its end.

- The Today link is gone from the row (`<today-link>` itself stays in the kit). Rows of today's class are still marked by `<today-marker>`.
- The month on screen is underlined and has `aria-current="location"`, set by a script in the component as the page scrolls. Each month link carries `data-first-week` and `data-last-week`, built from `scheduleMonths` (which now returns `last` as well as `week`).
- The Hide past weeks button, its status line and the `[data-schedule-tools]` wrapper moved from `<schedule-weeks>` into the row. `<schedule-weeks>` finds them in the page, so with no `<schedule-overview>` there is no toggle. The toolbar over the weeks is gone.
- The row is pinned from 640px wide, and the page's scroll padding follows its height so an anchor or a focused control is never under it. Below 640px it is a plain row.
- The key above the weeks shows the Test, Graded and Reading check chips alone; Practice keeps "not graded". `schedule.graded` is no longer a copy key.

A course that overrides `schedule-overview` or `schedule-weeks` takes these changes from the kit's copy: remove the Today link, move the toggle into the row, drop the toolbar, add the month mark. A course whose `strings.json` sets `schedule.graded` deletes it.

## The eyebrow above a page heading

The line of term and course code above the heading (`Fall 2026 · CS101`) repeated the masthead, so it is gone from the glossary, the schedule, the practice worksheet and the lesson plans index. A worksheet that sets `eyebrow` in its front matter still shows that label alone. `glossary.glossary` is no longer a copy key. The masthead does not print, but the footer does, with the course and the term; the syllabus's print-only term and title line stays, because the syllabus stylesheet hides the footer.

A course that overrides the glossary, `schedule-overview`, `practice-worksheet` or `layouts/lesson.webc` removes its own eyebrow the same way.

## 44px targets and the document source order

Several of the kit's own links are now 44px targets (WCAG 2.5.5): the home band's Coming up links, the This week card's links, the document layout's Contents rail, the lesson plan's outline, rail and previous/next/all-lessons links, the lesson index's links (now a list per row), a link that is a whole cell of a `.table-light` table, a link that is a whole paragraph of a disclosure, and the footer's course name, which reads as one run of text again.

- A course that overrides `layouts/lesson.webc` takes the list markup from the kit's copy.
- The document layout puts the page before its contents list in the source, so a screen reader reaches the page's h1 first. The grid is unchanged. A course that overrides `layouts/document.webc` takes the new order, and a stylesheet that selected `.doc-contents + .content-column` selects `.content-column + .doc-contents` now.

## The syllabus print and PDF margins

The printed syllabus and the syllabus PDF use matching `@page` margins that clear the page footer, paragraphs and list items use the full page width in print, and headings print in the hosted text face. A course whose own print stylesheet sets `@page` margins keeps them. `yarn check:pdf` checks a built PDF.

## The footer's Open source link

Set `institution.sourceUrl` to add an "Open source" link (the `nav.openSource` copy key) to every page's footer. It is off until set. A course that added its own footer link to a repository sets the option and deletes its link.

## Lessons with no demos

A `lessonDemos` that is not a list is treated as no demos, so a course can delete its `lessonDemos: []` workaround. `lessonDemos` is documented in [docs/components.md](../components.md).
